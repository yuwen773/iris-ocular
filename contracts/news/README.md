# Iris News Engine · Worker 协议 v1

[OpenAPI](openapi.json) 定义内部 HTTP 入口，[JSON Schema](v1.schema.json) 定义消息，[共享夹具](fixtures/v1.json) 用于 Python 和 WP-02 测试。Python 绑定改动时运行 `uv run python tools/export_schema.py`，并评审生成的 schema 与夹具差异。跨字段、授权和状态规则由协议实现在接收端执行。

## 认证与领取

- 控制面通过 HTTPS 服务 Worker，`X-Iris-News-Worker-Key` 映射到独立机器身份，只授权本 OpenAPI 声明的内部操作。权限判定须覆盖任务及租约归属。Worker 凭证不写入任务、下载请求或诊断。
- 领取返回 `200` 和固定租约，或 `204` 表示当前无任务。领取响应丢失后，服务端等待租约到期，再按重试策略处理。Java 服务端时间决定租约有效性，Worker 用单调时钟和剩余租约收紧本地截止时间。
- 每个窗口由 `source`、`sourceConfigVersion`、查询和日期范围确定。`startOn` 含当天，`endBefore` 排除当天，粒度为信源 API 的日历日。Java 保留各配置版本的已提交游标，首轮和配置变更显式指定起点。重叠回看范围由未来调度策略按信源配置。

## 批次、回执与原子完成

- 批次序号从 1 连续递增，每批最多 50 条。窗口最多处理 10,000 条上游记录，单个请求体最多 2 MiB。Worker 在一次执行内去除内容相同的重复记录，Java 按信源、稳定 ID 和内容修订幂等落库。内容摘要可由材料的 JSON 投影计算，去掉空可选字段，键按字典序递归排序，UTF-8 编码并以 SHA-256 摘要。
- 幂等键分别为 `<generation>:<sequence>`、`<generation>:complete`、`<generation>:fail`。Java 将键绑定到已认证机器身份、任务、代次、操作和请求体。本版本以请求体原始 UTF-8 字节的 SHA-256 判等。Worker 每次重试重复发送同一份字节。
- 认证及历史归属检查后，匹配的既有回执可重放，即使任务已进入终态或租约已过期。同键异体返回 `409 IDEMPOTENCY_CONFLICT`。新写入须在事务中确认机器身份、任务、执行代次、租约令牌和有效期。旧代次返回 `409 STALE_LEASE`，无法提交新批次或推进游标。
- 完成时 Java 校验批次序号无缺口，且各回执记录数之和等于 `recordCount`。该计数为入库去重前上报条数。空窗允许批次和记录数均为零。提交的 `nextCursor` 必须等于窗口上界，并与已提交游标和配置版本做并发仲裁。在一个事务中写入完成状态、最终回执、编辑可见性和游标。
- 已接收的部分批次可用于回执核对，整窗完成后资料才可供后续编辑。失败、超时或进程中断均保留旧游标，后续代次整窗重跑。Java 决定退避、最大任务尝试次数和失败终态。完成结果不明时 Worker 在有效预算内重放完成请求，超出预算交由服务端按持久化完成回执判断。

## 语义校验

两端以 [反例夹具](fixtures/v1.invalid.json) 校验 JSON Schema 之外的约束。窗口开始日须早于截止日。查询、标题和已提供的语言、DOI、摘要字段须含非空白文字。资料来源链接须含 HTTPS 主机且不含用户名或密码。部分出版日期采用 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`，并须为有效日历日期。摘要与许可成对提供。完成时应满足 `batchCount ≤ recordCount ≤ 50 × batchCount`，并进一步核对实际批次与已分配窗口。接收端拒绝不符合约束的消息，游标保持原值。

## 连接与数据边界

原站时间、采集窗口和现有 `t_news.publishTime` 分别表达来源日期、任务范围和发布业务字段。采集资料按信源保留，原站缺失字段可空。试验上报有限结构化字段，文章摘要由适配器按许可保守保留。所有正文类字段都按外部不可信内容处理。对外展示、临床证据检索和模型调用由后续独立门禁授权。

Java 实现仍需用共享夹具、真实 MySQL 并发与故障用例验证。Mock Java 的内存状态用来给 Worker 离线验收和对齐契约。
