# WP-08 · 资讯引擎后续工作项（当前**未**实现）

本文件是交付口径的负向清单：把「本分支**没有**做、也不该被读成做了」的能力写清楚，
避免文档、PR 正文或口头汇报里出现「已经能自动采集 / 已经接了模型」这类不成立的表述。

范围纪律：本 PR（News Engine 开发线）**不**实现下列任何一项，也不为其预留半成品开关。
每一项都需要单独的设计、评审与灰度授权。

## 1. 自动采集调度与生产定时部署

**代码事实（当前）**

- Worker 只有一个执行形态：`news-worker` 的 `run-once`（`iris_news_worker.cli` → `Worker.run_once`）。
  进程取一批窗口、跑到时间预算或取空即退出，全仓库**没有** cron、systemd timer、K8s CronJob
  或任何常驻调度器。
- Java 控制面只负责**把窗口派出去**：`t_news_collection_task` 由管理员手动入队
  （`POST /api/admin/news-workbench/tasks/enqueue`）或由外部流程写入；
  Worker 通过 `POST /api/internal/news/v1/leases/claim` 领取。
- 因此「每天自动开新窗口」这件事**当前不存在**：窗口不会自己出现。
- WP-07 灰度记录里讨论的「固定锁路径 + 非阻塞串行执行 `run-once`」是**部署约定**，
  仓库内没有实现该约定的脚本或服务。

**进入 WP-08 的条件**

1. 明确调度归属：Java 侧开窗（写 `t_news_collection_task`）还是外部编排器开窗。两者只能选一个。
2. 窗口推进策略与游标语义对齐：`sourceConfigVersion` 何时升版、失败窗口如何处置、
   是否允许人工「放弃窗口」（当前明确不允许：系统不自动跳过失败窗口）。
3. 互斥与幂等：同一 `(source, sourceConfigVersion)` 不得有两个调度器同时开窗；
   调度触发必须可重入（重复触发不产生重复窗口）。
4. 灰度授权：先在目标环境以单信源、小窗口跑通，再逐源放开。

**验收口径**

- 连续 N 个调度周期内，窗口按策略自动出现，且失败窗口**停在原地**并出现在工作台的阻塞原因里；
- 重复触发不产生重复窗口；
- 调度日志与 `t_news_collection_task_event` 的操作审计能对上。

## 2. 真实模型 Provider 适配

**代码事实（当前）**

- 精选侧注入的默认实现是 `DisabledNewsCurationModelClient`：
  任何调用都直接失败，**不会**发出任何 HTTP 请求，也不产生任何付费调用。
- `eye-diagnosis.news-curation.enabled` 默认 `false`；`provider` / `model-name` / 预算上限
  （`daily-max-calls`、`daily-max-tokens`、`daily-max-cost-micros`）只是**配置骨架**，
  真实 Provider 适配器尚未接入。
- 已经落地的是**围绕调用的一切外围机制**：预扣与结算、幂等回执、`OUTCOME_UNKNOWN` 的
  人工对账、鉴权失败熔断与人工恢复、NewsBench 门禁。这些机制在真实适配器接入前不会被触发。
- 因此「模型精选已上线」是不成立的说法；准确说法是「精选的预算与回执机制已就绪，模型调用本身未接入」。

**进入 WP-08 的条件**

1. 明确 Provider、模型与数据出境边界（资讯摘要是否允许出境，摘要许可是否覆盖）。
2. 预算熔断、幂等回执、对账流程在真实调用下重新验证一遍（当前只在夹具与离线回放下验证过）。
3. 失败语义复核：`FAILED_DEFINITIVE` / `OUTCOME_UNKNOWN` 在真实 Provider 的返回形态下的映射。
4. 付费调用需要**单独授权与明确的调用上限**，不能沿用离线验收的额度。

**验收口径**

- 真实调用 0 元的默认配置下，采集与发布链路仍然可用（精选关闭不影响采集）；
- 开启精选后，预算上限被真实触发时熔断，且事后可对账。

## 3. NewsBench 数据集扩充

**代码事实（当前）**

- NewsBench 门禁已要求三类样本齐备（对抗样本、许可样本、注入样本），缺样本即判失败。
- 但数据集本身仍是仓库内的**冻结夹具**，样本量与覆盖面没有扩充。
- 扩充数据集需要人工评审：每条样本要能追到公开来源、许可与预期判定，
  不能由模型自行生成后直接入库。

**进入 WP-08 的条件**

1. 抽样规则与许可核验流程成文；
2. 每条新样本有可核验的来源与预期判定记录；
3. 扩充后重新给出基线分数与回归对比。

**验收口径**

- 门禁在扩充后的数据集上仍能通过，且失败样本能被定位到具体判定条目。

## 保留的限制（本 PR 不放宽）

- **真实信源限制**：PubMed 与 ClinicalTrials.gov 在当前灰度环境被 SNI 过滤阻断，
  需要具备正常公网出站的环境重跑正式 Worker（见 [WP-07 验收记录](wp-07-canary.md)）。
- **目标环境性能限制**：本机基线采集期公读 P95 增幅 **+12.59%**，超过 10% 设计目标；
  目标环境 P95 与门槛判定仍为 `NOT_RUN`，不能记为达标。
- **付费调用限制**：本 PR 全程付费模型调用 **0 次**；预算熔断与对账机制只有离线验证，
  真实额度需单独授权。
- **采集与精选开关**：采集与自动发布、模型精选均默认关闭，
  「合并进主干」不等于「在生产启用」。
