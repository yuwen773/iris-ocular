# WP-08 · 资讯引擎后续工作项

真实模型、NewsBench 扩充和生产灰度各自需要单独的设计、评审与授权。

## 1. 自动采集调度与生产定时部署

WP-08A 已合入主干并关闭。目标环境按单信源、小窗口灰度。见 [WP-08A 调度设计与运维](wp-08a-scheduling.md)。

## 2. 真实模型 Provider 适配

WP-08B.0 / B.1 的统一 OpenAI Compatible 适配器、调用回执与模型实验协议见 [资讯精选契约](wp-08b-model-curation.md)。`eye-diagnosis.news-curation.enabled` 默认关闭。真实供应商联调、分层生成接入、人工标注与付费 A/B 留待后续授权。

**进入真实模型联调的条件**

1. 明确 Provider、模型与数据出境边界（资讯摘要是否允许出境，摘要许可是否覆盖）。
2. 预算熔断、幂等回执、对账流程在真实调用下重新验证一遍（当前只在夹具与离线回放下验证过）。
3. 失败语义复核：`FAILED_DEFINITIVE` / `OUTCOME_UNKNOWN` 在真实 Provider 的返回形态下的映射。
4. 付费调用需要**单独授权与明确的调用上限**，不能沿用离线验收的额度。

**验收口径**

- 真实调用 0 元的默认配置下，采集与发布链路仍然可用（精选关闭不影响采集）；
- 开启精选后，预算上限被真实触发时熔断，且事后可对账。

## 3. NewsBench 数据集扩充

**代码事实（当前）**

- NewsBench 门禁已要求三类样本齐备（对抗样本、许可样本、注入样本），缺样本即判失败。
- 但数据集本身仍是仓库内的**冻结夹具**，样本量与覆盖面没有扩充。
- 扩充数据集需要人工评审：每条样本要能追到公开来源、许可与预期判定，
  不能由模型自行生成后直接入库。

**进入 WP-08 的条件**

1. 抽样规则与许可核验流程成文；
2. 每条新样本有可核验的来源与预期判定记录；
3. 扩充后重新给出基线分数与回归对比。

**验收口径**

- 门禁在扩充后的数据集上仍能通过，且失败样本能被定位到具体判定条目。

## 保留的限制（本 PR 不放宽）

- **真实信源限制**：PubMed 与 ClinicalTrials.gov 在当前灰度环境被 SNI 过滤阻断，
  需要具备正常公网出站的环境重跑正式 Worker（见 [WP-07 验收记录](wp-07-canary.md)）。
- **目标环境性能限制**：本机基线采集期公读 P95 增幅 **+12.59%**，超过 10% 设计目标；
  目标环境 P95 与门槛判定仍为 `NOT_RUN`，不能记为达标。
- **付费调用限制**：本 PR 全程付费模型调用 **0 次**；预算熔断与对账机制只有离线验证，
  真实额度需单独授权。
- **采集与精选开关**：采集与自动发布、模型精选均默认关闭，
  「合并进主干」不等于「在生产启用」。
