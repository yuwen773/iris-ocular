## 1. 目标与边界

1. 用**免费额度**完成真实 Provider 验证：P05 单模型策略 A 能否稳定产出通过 Java 契约的结构化结果；
2. 验证回执里的 `logicalCallSha256`、token 与费用字段能与账单对上；
3. 验证预算闸门（日上限、整次实验总上限、熔断）在真实返回形态下按预期触发，且**免费额度耗尽**被单独识别。

不做：双模型对照、A/B 标注、NewsBench 扩量、生产发布、自动发布、任何患者数据出境。
不新增微服务，不建设免费额度管理平台，不提前实施 B3–B5，不改生产开关。

## 2. 官方免费额度规则（已按官方页面核对）

来源：<https://help.aliyun.com/zh/model-studio/new-free-quota>（2026-11-27 读取）。原文要点：

| 规则 | 官方原文 | 对我们的约束 |
| --- | --- | --- |
| 地域 | 「仅华北2（北京）地域模型享有免费额度，其他地域无免费额度。」 | 只用北京地域端点 |
| 密钥 | 「API Key 本身不绑定特定模型，同一个 API Key 可调用所有模型」；「Token Plan/Coding Plan 专属 API Key 不消耗免费额度。」 | 只用**通用 API Key**，不得用套餐专属 Key |
| 调用方式 | 「免费额度仅抵扣模型实时推理（调用）产生的费用。」 | 只用实时 OpenAI-Compatible Chat Completions |
| Batch | 「免费额度不支持抵扣OpenAI兼容-Batch（文件输入）产生的费用。」；「Batch调用、模型调优、模型部署、自定义模型…不支持用免费额度抵扣。」 | 禁止 Batch 与任何离线批处理 |
| 计数口径 | 「不同模型（含同一模型的不同快照版本）的免费额度相互独立，不互通、不共享。」；快照与最新版「视为两个独立模型，各自拥有独立额度」 | `qwen3.8-max-0902` 与 `qwen3.8-max` **分别计数**，实验只用快照 |
| 账号 | 「阿里云主账号与其RAM子账号共享免费额度。」 | 主/RAM 共用，估算时不得假设有两份额度 |
| 用完即停 | 「该功能默认关闭」；开启后额度用尽「返回 HTTP 403 错误，错误码为 `AllocationQuota.FreeTierOnly`」 | **必须在调用前确认该模型的「用完即停」已开启**，否则超额会自动转为按量付费 |

| 项 | 取值 | 依据 |

整次实验费用闸门仍设为 **¥5.00**：它不是付费授权，而是「如果免费额度失效，最多只会走这么远」的安全阀。
免费额度生效时实际支付应为 **0 元**；出现任何非零应付即为停止条件。

## 4. 调用与预算上限

| 项 | 上限 | 落地字段 |
| --- | --- | --- |
| 实际请求数 | 20 次（含任何显式重试） | `lifetime-max-calls: 20` |
| Token | 200,000（按 20 × (8192 + 1024) 的包络，低于 1M 免费额度） | `lifetime-max-tokens: 200000` |
| 标准费率费用 | ¥5.00 | `lifetime-max-cost-micros: 5000000` |
| 日上限 | 20 次 / 200,000 token / ¥5.00 | `daily-max-*` 同值 |
| 单次预留 | 按 profile 费率算出的上限值预占 | `reserveAttempt` |

四道闸门语义不变：**预扣 → 耗尽即拒（不发请求）→ 鉴权熔断 → `OUTCOME_UNKNOWN` 对账**。
锁定顺序固定为 circuit → 日守卫 → scope 预算 → 整次上限 → 回执 → 候选。

## 5. 错误分类（本轮代码改动）

`NewsOpenAiCompatibleModelClient.classifyError` 现在把「免费额度耗尽」从鉴权失败里拆出来：

| 情形 | 判定依据 | 结果 | 后果 |
| --- | --- | --- | --- |
| 免费额度用尽（用完即停） | HTTP 403 + `error.code = AllocationQuota.FreeTierOnly` | `MODEL_FREE_QUOTA_EXHAUSTED` | 确定性失败；**不重试、不切换模型、不触发鉴权熔断**；预留额度退回，回执 `FAILED_DEFINITIVE` |
| 欠费 | HTTP 403 + `Arrearage`（`error.code` 或顶层 `code`） | `MODEL_BALANCE_INSUFFICIENT` | 同上，不熔断 |
| 鉴权失败 | 其他 401/403 | `MODEL_AUTH_REJECTED`，`authFailure = true` | 熔断该 scope，直到管理员显式重置 |
| 速率限制 | HTTP 429 | `MODEL_RATE_LIMITED`（`UnknownOutcome`） | 保留预留，人工对账，不自动重发 |
| 应用预算耗尽 | 预扣阶段 | `BUDGET_EXHAUSTED` / `LIFETIME_BUDGET_EXHAUSTED` | 请求根本不发出，不产生新回执 |

单次尝试（`maxAttempts = 1`、HTTP/1.1、禁重定向）由传输层保证；没有任何「换模型重试」代码路径。

## 9. 运行时调用入口（2026-11-28 已解除）

2026-11-27 的阻塞事实是：`git grep "runModel(" -- src/main` 只有 `NewsCurationService` 自身重载，
管理端没有会发起模型调用的入口。2026-11-28 的运行时闭环工作补上了窄入口：

- `POST /api/admin/news-workbench/materials/{materialRevisionId}/curate`（仅管理员）；
- 入口以 `Selection("production", Prompt.P05, profileKey, null)` 调用既有 `runModel`，复用
  预扣、四道闸门、整次上限、回执、熔断与幂等重放；
- 模型 profile 由服务端 `run-profile-key` 裁决，请求体不含模型字段；
- 证据路由为 SKIP 时在预扣前拒绝；成功回执需管理员显式转待审候选，不自动建稿或发布。

实现细节、错误语义与隔离验收见 `wp-08b2-runtime-closure.md`。
**G-7 解除只表示入口可用，不构成真实调用授权**；G-1…G-5 仍为未确认。
